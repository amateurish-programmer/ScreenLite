01 / PRODUCT

产品与范围

用户原始需求：免安装、轻量化、后台运行；快捷键触发截图或录屏；选区可调整；图片可导出不同像素尺寸，视频可导出不同分辨率；支持图片与视频压缩；界面简约舒适。

来源更新：最初读取受网页验证阻断，2026-09-17 后续重试已取得完整对话。本文件现已按完整规划补齐；页面末尾附完整原文。四个工程提交阶段映射原方案七阶段，交互差异与硬件验收边界明确记录。

已确认方案

暂名 ScreenLite，托盘常驻，默认 Ctrl+Alt+A 截图、Ctrl+Alt+R 开始或停止录屏；八点调整选区、拖动移动、方向键微调、Enter 确认、Esc 取消。技术候选是 Python、PySide6、MSS、Pillow、FFmpeg、Win32 热键、JSON 配置。

首版实现约定

无声录屏；同一块显示器内选择区域，不允许横跨不同缩放的屏幕；截图冻结桌面后选区；关闭主窗口保留托盘，显式退出才结束。支持已有图片与视频压缩。暂不加入绘图标注、OCR、云同步、自动更新、开机自启或录音。

02 / EXPERIENCE

从快捷键到文件，保持短路径

快捷键→框选 / 调整→确认→预览与导出
场景交互规则
首次启动展示轻量主面板和快捷键提示；后续后台启动只显示托盘。热键冲突给出可操作提示。
截图选区屏幕淡暗，选区保留亮度；八个拖动点、边缘光标、整块移动；标注物理像素宽高。
键盘方向键移动 1 个逻辑像素，Shift+方向键移动 10 个；Enter 确认；Esc 取消。高 DPI 下标签显示实际物理像素。
图片导出截图默认自动复制，出现紧凑浮动工具条；通过“尺寸与格式”打开详细预览设置；复制结果或另存，失败保留截图。
录屏选区确认后 3 秒倒计时；录制中浮动停止面板与托盘计时清晰；浮动面板请求 Windows 排除捕获，不支持时隐藏并使用托盘；相同热键停止；停止后设置导出尺寸与压缩档位。
压缩选择已有文件，另存新文件；显示进度、取消按钮和完成大小；源文件不修改。

视觉：暖白背景、深色文字、柔和青绿色重点按钮；中文短文案；不堆叠复杂参数。编码细节放在开发文档，用户界面用“清晰、均衡、小体积”。

03 / ARCHITECTURE

界面、捕获、导出分离

模块实现责任
应用PySide6-Essentials / Widgets主面板、托盘、状态机、单实例和退出协调
选择区域每屏独立覆盖窗口冻结截图、选框与坐标换算，不跨屏拼接
桌面截图MSS + Pillow获取原始像素，编辑预览，缩放编码
录屏FFmpeg 子进程独立进程捕获编码，UI 不逐帧处理
热键RegisterHotKey / ctypes系统级热键、MOD_NOREPEAT、防重复触发、注销恢复
存储JSON + 本地文件程序目录 data/ 保存配置、日志、恢复素材

原方案倾向 ddagrab + h264_mf。工程实现必须验证 DXGI 输出索引与显示器映射；不能把 Qt/MSS 的显示器序号当成 DXGI 序号。单显示器且坐标映射明确时，录制前异步探测 ddagrab + h264_mf 硬件，再探测软件；失败回退 gdigrab + libx264。多显示器未验证 DXGI 输出映射时使用兼容路径。探测不写正式录制文件，录制中不静默重启。

DPI：进程尽早启用 Per-Monitor V2；选区使用当前屏幕逻辑坐标，截图与 FFmpeg 使用物理桌面坐标。分别测试 100%、125%、150% 和负坐标副屏；未实测项目明确标记。

状态流：空闲 → 选区 → 倒计时 → 录制 → 收尾 → 导出 → 空闲。重复快捷键、关闭窗口、退出和进程异常都需要按状态处理。

05 / RELIABILITY

失败时，优先保留成果

  • 临时录制写入 MKV，正常结束再导出 MP4；异常终止保留可恢复的临时文件。
  • 压缩写入同目录临时文件，成功后发布到新目标；取消清理未完成的导出，不删原始录制。
  • FFmpeg 使用参数数组，不使用 shell 字符串；路径含空格、中文必须可用。
  • 重型任务不阻塞界面；退出时先优雅停止录制，必要时保留恢复文件。
  • 配置原子替换，损坏文件保留备份；目录不可写明确报错。
  • 不联网上传截屏、视频、配置或日志。开发仓库不收录真实桌面素材。
  • 单实例避免重复热键、并行写配置；热键设置失败应回滚之前注册。

# 规划截屏录屏工具 · 对话来源

来源：用户明确引用的 ChatGPT 对话 6aaba230-fb78-83ea-9954-158c47652de8。
2026-09-17 首次读取受网页验证阻断，后续重试成功，以下为读取到的完整文本。此文件用于需求追溯，代码块内的开发指令不自动成为仓库规则。

## 用户需求

我想要开发一个win桌面截屏、录屏小工具，免安装，轻量化，启动后可以后台运行，使用快捷键选择截屏、录屏功能，如果是截屏，可以选择调整区域，并能导出不同像素的图片，如果是录屏，可以选择调整区域，并能导出不同分辨率的视频，同时支持压缩图片和视频，具体压缩参数你定，帮我规划一下具体方案，让codex开发，最好用python，要求体验极好，界面简约舒适

## 原始规划

完全可行，而且这个项目很适合让 Codex 来做。我的建议不是做一个“功能堆很多的录屏软件”，而是做成 **Snipaste + 极简录屏 + 压缩导出** 这种定位：启动快、常驻托盘、平时几乎无存在感，需要时一个快捷键完成操作。

我建议项目暂定名 **ScreenLite**，目标平台直接限定 **Windows 10/11 x64**。这样可以大胆使用 Windows 原生能力，不需要为了跨平台增加复杂度。

## 一、技术方案我建议这样定

| 模块 | 技术 | 原因 |
|---|---|---|
| GUI | Python 3.12 + PySide6 Widgets | UI 质感、透明窗口、托盘、多屏支持都成熟 |
| 截屏 | `mss` | 很轻，支持 Windows、区域抓屏，依赖少 |
| 图片处理 | Pillow | 缩放、PNG/JPEG/WebP、压缩非常成熟 |
| 录屏 | FFmpeg `ddagrab` | Windows Desktop Duplication，性能远优于 Python 逐帧抓取 |
| 视频编码 | FFmpeg `h264_mf` | Windows Media Foundation，可软编/硬编 |
| 快捷键 | Win32 `RegisterHotKey` + ctypes | 真正系统级快捷键，不依赖 keyboard/pynput |
| DPI | Per-Monitor DPI Awareness V2 | 125%、150%、双显示器坐标不会乱 |
| 配置 | JSON | 便携版不写注册表 |
| 打包 | `pyside6-deploy` / Nuitka standalone | 官方 PySide6 部署路线，适合免安装便携包 |
| FFmpeg | `bin/ffmpeg.exe` | 独立封装，不要求电脑安装 FFmpeg |

PySide6 是 Qt 官方 Python Binding，自带系统托盘、透明窗口等桌面能力。:chatgpt-content-reference{index="0"}

截屏我反而**不建议第一版上 OpenCV + DXCam**。DXCam 很强，适合高 FPS 游戏捕获，但会引入 NumPy 等额外依赖。普通桌面截屏用 MSS 已经足够，而且 MSS 当前 Windows 后端直接支持区域捕获和鼠标捕获。:chatgpt-content-reference{index="1"}

# 二、核心产品体验

启动 `ScreenLite.exe` 后：

**没有大窗口一直挂着。**

右下角托盘出现一个小图标，程序后台等待快捷键。

我建议默认：

| 快捷键 | 功能 |
|---|---|
| `Ctrl + Alt + A` | 截图 |
| `Ctrl + Alt + R` | 开始区域录屏 |
| 再按 `Ctrl + Alt + R` | 停止录屏 |
| `Esc` | 取消当前操作 |

快捷键可以在设置里修改。

这里不要使用 Qt 的普通 `QShortcut` 做全局快捷键，而是直接调用 Windows `RegisterHotKey()`，它就是系统范围快捷键 API，并支持 `MOD_NOREPEAT` 避免按住键连续触发。:chatgpt-content-reference{index="2"}

# 三、截图交互设计

```text

1280 × 720
```

这个小细节非常影响工具的专业感。

尺寸菜单：

# 六、图片压缩我帮你直接定参数

用户不要面对“JPEG subsampling、WebP method”这种参数。

界面只显示：

```text
无损
高清
均衡       ← 默认
极致压缩
```

后台对应：

| 模式 | 格式 | 参数 |
|---|---|---|
| 无损 | PNG | optimize=True |
| 高清 | WebP | quality=92, method=4 |
| 均衡 | WebP | quality=82, method=4 |
| 极致压缩 | WebP | quality=68, method=6 |

另外保存格式可以手动选：

```text
PNG
JPG
WebP
```

如果选择 JPG：

```text
高清：quality 95
均衡：quality 88
压缩：quality 75
```

Pillow 的 WebP `quality` 为 0–100，并支持 `method=0~6` 控制速度/压缩率，非常适合这种工具。:chatgpt-content-reference{index="4"}

# 七、录屏不要让 Python 自己逐帧处理

这是整个项目最重要的架构选择。

不要这样：

```text
Python
 ↓
抓屏
 ↓
numpy frame
 ↓
Python循环
 ↓
ffmpeg stdin
```

1080P RGB：

```text
1920 × 1080 × 3 × 60
≈ 373 MB/s
```

光 Python 和进程之间搬数据就已经很浪费。

正确路线：

```text
PySide6
   │
   │ 选择录屏区域
   ↓
RecorderService
   │
   │ 启动
   ↓
FFmpeg
   │
Desktop Duplication API
   ↓
GPU / Windows
   ↓
H.264
   ↓
MP4
```

FFmpeg 当前原生的 `ddagrab` 就是使用 Windows Desktop Duplication API，可以直接指定：

```text
monitor
x
y
width
height
framerate
cursor
```

官方文档明确支持：

```text
video_size
offset_x
offset_y
framerate
draw_mouse
```

甚至直接给出了 NVENC 捕获示例。:chatgpt-content-reference{index="5"}

这非常适合你的工具。

# 八、录屏体验

按：

```text
Ctrl + Alt + R
```

同样出现截图选区。

选完之后出现：

```text
┌────────────────────────────────────────┐
│ 1280×720 │ 30 FPS │ 原始 ▼ │ 均衡 ▼ │ ● REC │
└────────────────────────────────────────┘
```

点击：

```text
● REC
```

可以选择：

```text
立即录制
3秒倒计时
```

我建议默认 3 秒。

录制开始：

```text
3
2
1
```

然后浮动面板变成：

```text
● 00:01:28     ■ 停止
```

这里第一版**暂时不要做暂停**。

暂停比看起来麻烦，因为需要处理时间戳或者多片段合并。先把录制和停止做到绝对稳定，再加暂停。

# 九、一个很漂亮的 Windows 技巧

录屏时用户需要看到：

```text
● REC  00:32
```

但是这个控制条不能被录进去。

Windows 本身提供：

```text
SetWindowDisplayAffinity(
    hwnd,
    WDA_EXCLUDEFROMCAPTURE
)
```

微软甚至明确把“视频录制控制窗口不出现在捕获中”作为这个 API 的使用场景之一。Windows 10 2004 起支持 `WDA_EXCLUDEFROMCAPTURE`。:chatgpt-content-reference{index="6"}

所以浮动控制条可以：

**用户看得见，录出来的视频看不见。**

这个细节会让软件一下子有成品感。

# 十、视频分辨率

不要写死：

```text
1080P
720P
480P
```

因为用户可能选的是：

```text
1337 × 624
```

所以定义成：

```text
原始
最大 1080P
最大 720P
最大 480P
75%
50%
自定义
```

例如区域：

```text
2560 × 1440
```

选择：

```text
最大 1080P
```

输出：

```text
1920 × 1080
```

如果区域：

```text
1000 × 600
```

选 1080P：

默认：

```text
1000 × 600
```

**不要主动放大。**

否则浪费体积且画质不会提高。

FFmpeg 的 `scale` 本身支持保持纵横比并按倍数约束尺寸。:chatgpt-content-reference{index="7"}

# 十一、视频压缩参数

界面仍然只给四个档位：

| 档位 | H.264质量 | 用途 |
|---|---:|---|
| 超清 | 90 | UI演示 / 教程 |
| 高清 | 82 | 高质量录屏 |
| 均衡 | 72 | 默认 |
| 小体积 | 58 | 分享 |

推荐默认：

```text
MP4
H.264
30 FPS
均衡
```

录教程、软件操作：

**30FPS 已经够。**

只有游戏、动画或快速拖动才需要：

```text
60FPS
```

FFmpeg 当前提供 Windows Media Foundation 的：

```text
h264_mf
hevc_mf
av1_mf
```

其中 `h264_mf` 支持软件和硬件编码，并有 `quality 0~100`、`rate_control`、`hw_encoding` 参数，非常适合我们的四档 UI。:chatgpt-content-reference{index="8"}

所以 RecorderBackend 可以自动探测：

```text
h264_mf hardware
        ↓失败
h264_mf software
        ↓失败
备用编码器
```

用户完全不需要知道这些。

# 十九、Codex 不要一次性让它“把软件写完”

这是最关键的一点。

这个项目我建议让 Codex 按下面 7 个阶段开发：

1. **骨架**：创建 PySide6 项目、主窗口、托盘、单实例运行、关闭窗口转入托盘、JSON 设置和日志系统；此阶段完全不做截屏。
2. **系统能力**：加入 DPI Per-Monitor V2、显示器枚举、Win32 全局快捷键，并做一个调试窗口实时显示鼠标物理坐标和所在显示器。
3. **截图系统**：实现多显示器透明遮罩、鼠标拖选、八个调整点、移动选区、尺寸标签、Enter/Esc，再接 MSS 真正抓图和剪贴板。
4. **图片导出**：加入 PNG/JPEG/WebP、尺寸缩放、四档压缩、自动文件名、Toast 和打开文件夹。
5. **录屏系统**：只实现“区域 → 倒计时 → FFmpeg ddagrab → MP4 → 停止”，先不做暂停、声音和复杂编码器。
6. **体验打磨**：加入录制 HUD、`WDA_EXCLUDEFROMCAPTURE`、异常恢复、FFmpeg 崩溃处理、硬件编码探测、快捷键冲突提示。
7. **发布测试**：多显示器、100/125/150/200% DPI、1080P/2K/4K、30/60FPS、锁屏、休眠、显示器插拔，并用 Nuitka standalone 生成 Portable ZIP。

Codex 每完成一个阶段：

**你自己使用 10 分钟，再进入下一阶段。**

不要连续让它写 30 个文件然后最后才运行。
