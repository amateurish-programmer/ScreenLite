# v0.2 图片内存测量

2026-09-17，Windows 10 x64、Python 3.12.12，使用 `scripts/check_memory.py`。
每轮用合成 3840×2160 图像模拟桌面，裁切约 1920×1080 后打开导出工具条，再取消一次选区、打开关闭一次设置。
禁用真实桌面获取、剪贴板复制和热键。驱动处理 Qt 延迟销毁并执行 Python 垃圾回收，未调用工作集缩减 API。

同机独立进程，预热 5 轮，再各运行 30 轮：

| 指标（MiB） | v0.1.0 `048dfab` | v0.2.0 |
| --- | ---: | ---: |
| 选区阶段专用内存中位数 | 135.82 | 92.07 |
| 导出工具条阶段专用内存中位数 | 152.21 | 68.30 |
| 30 轮后专用内存 | 98.97 | 71.27 |
| 30 轮后工作集 | 113.15 | 135.29 |
| 残留设置窗口数 | 35 | 0 |

导出阶段专用内存下降约 55%。工作集未同步下降，Qt/系统缓存和分配器保留会影响工作集，不能据此宣称所有内存指标均下降。
进一步运行 v0.2.0 100 轮（另加 5 轮预热），最后 30 轮专用内存在 60.61–75.51 MiB 范围，最终 75.50 MiB，设置窗口残留仍为 0；未观察到旧版按设置窗口数量增长的现象。

代码层的回归验证包括：整屏 Pillow 引用在覆盖窗口建立后消失；导出工具条打开前所有整屏 Qt 缓冲已清空；窗口释放后图像可回收；编码线程成功结束后源引用清空；设置窗口不累积。

这些数据是合成图片工作流的测量，不是整机所有硬件、真实长时录屏或每种输入法的性能保证。剪贴板最终截图属于有意保留的数据，实际复制后占用会增加。关闭软件后由操作系统回收整个进程。

复现：

```powershell
.venv\Scripts\python.exe scripts/check_memory.py --cycles 100 --output .work/memory.json
```
